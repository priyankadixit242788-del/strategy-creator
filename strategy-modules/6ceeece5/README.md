For each trading date, this screener evaluates only the 09:15–09:20 IST 5-minute opening candle. It calculates `lo = min(open, close)` and `hi = max(open, close)` and requires `lo < X < hi` for ALL four stored levels: `sma20`, `sma50`, `sma200`, and `superTrend`. Wick-only crossings, equality, dojis, missing/non-finite OHLC or indicators, and non-positive opening prices fail. A later candle cannot replace a missing opening candle. Displayed range remains `high - low`, not body size.

The universe is recomputed independently for each date from each stock's latest daily candle within the last 10 trading sessions (dates with 5-minute candles), including the scan date when available, never subsequent dates. Rank by that candle's volume descending, with symbol ascending for ties, and take 300. Do not sum volumes or traded values. Exclude symbols ending in CE, PE, or FUT (case-insensitive) and the configured NIFTY index. Missing/non-finite or negative latest volume excludes the stock; do not substitute an older volume. `/scan` exposes numeric `universe_size` (default 300, range 1–300) and `liquidity_lookback` (default 10, range 1–90). History before `from_date` can supply liquidity data. Ranking and opening-candle retrieval happen in bounded, per-date ClickHouse queries, not by loading the full candle range into Python.

NIFTY direction comes from its own 09:15 IST candle: close above open is BUY, below is SHORT. Stock direction is defined the same way. `/scan?nifty_direction_filter=yes` (default) rejects a stock whose direction disagrees with NIFTY. `no` disables that filter; any other value falls back to `yes`. Missing/non-finite NIFTY open/close or a NIFTY doji means no direction filter is applied.

The confirmed table shows **all qualifying stocks**, without a default cap, while `calculations` separately reports the **one selected trade per day**. Among qualified stocks select the largest `pct = abs(close - open) / open * 100`, breaking ties alphabetically by symbol. Selection is independent of table sorting and `limit`. Each date's calculations include NIFTY inputs/direction, each universe stock's inputs, body bounds, per-indicator crossing checks, qualification/rejection reason, qualified percentages, selected symbol, and TRADE/NO TRADE status. Missing data stops the affected calculation step; no prices or indicators are invented. This is a screener/selection endpoint, not a trade execution or stop/target backtest.

By default scan the last **60 trading sessions** ending at the latest date with 5-minute candles. `/scan` accepts inclusive `from_date` and `to_date` (`YYYY-MM-DD`); equal dates scan a single session. Invalid/reversed ranges or applied spans over 90 calendar days return HTTP 400 with `{"success": false, "error": "<reason>"}`. Trading dates and opening times use Asia/Kolkata explicitly. Return one row per qualifying stock/date, grouped newest date first. `sort_by` (default `scan_date`) and `sort_dir` (default `desc`) control ordering within dates. `limit` defaults to 0 (unlimited); positive caps apply independently per date, and `total` counts all qualified matches before capping.

The response supplies the applied/available date bounds and trading dates for the viewer's from/to filter. The Ranked Table columns are Symbol, scan_date, High, Low, range, and Candle time, with symbol search and sortable headers. Presentation uses numbered pages of **10** results; pagination is a viewer setting and does not truncate the API's matches. SuperTrend is a condition, not an output column.

Deployment uses `stock__candles_data` with `stock`, `interval`, `date`, `open`, `high`, `low`, `close`, `volume`, and the four indicator columns. The repository does not establish the external database's daily interval or NIFTY symbol encoding: set `CLICKHOUSE_DAILY_INTERVAL` (default `day`) and `CLICKHOUSE_NIFTY_SYMBOL` (default `NIFTY 50`) to match the deployment. These are bound query values, not SQL fragments. The 5-minute interval is fixed at `5`. Incorrect/missing source encodings produce an empty universe or missing NIFTY diagnostics, not synthetic data.

Run module tests from this directory with `python -m pytest -q test_scan.py` after installing the existing `requirements.txt`.
